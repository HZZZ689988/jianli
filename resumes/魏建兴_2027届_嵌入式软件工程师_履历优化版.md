## 项目经历

### STM32F103 + RK3562 手持控制终端

<p class="project-meta">STM32F103RCT6 负责按键、电源、电量和外设控制，RK3562 Android 负责显示、网络和上层服务，两端通过 UART 通信，并接入 CAN、MAVLink 与图传链路。</p>

- 负责 STM32F103RCT6 固件开发，用 FreeRTOS 运行按键/电源、电量、UART/CAN 和状态监控逻辑。IWDG 由独立任务刷新，每 500 ms 检查主业务循环的最后活跃时间，超过 2 s 未更新便停止喂狗，同时在启动日志中记录复位原因。
- 为电源键加入 50 ms 去抖和短按、2 s 长按判断：短按显示电量或配合 RK 侧息屏/唤醒，关机态长按上电，开机态长按进入软关机。通过 PWRON 与 RK3562 协同深睡眠和软关机，并在断电前预留安全关机时间；联调中处理过连续短按后主控无法亮屏和控制脚状态异常的问题。
- 使用 PB1 ADC 采样估算电量并驱动四颗 LED 分档显示；接入 CH224 充电检测，充电时让下一档 LED 闪烁。GPS 和 QMA6100P 加速度计也在同一固件中完成接入和日志验证。
- 设计 RK-MCU 二进制串口协议，帧格式为 `0xA5 + type + seq + len + TLV + CRC16-CCITT`，支持 `HELLO`、状态摘要、命令和 `ACK/ERROR`。轮询接收时出现过短命令帧漏收，后改为 USART2 中断接收和环形队列解析。
- 在 RK3562 的 `/dev/ttyS3` 上抓取 16 帧连续状态数据，全部通过 CRC16 校验；随后发送 `request_id=0x1234` 的状态请求并收到成功 ACK。板端没有 Python 环境，因此另外写了纯 Shell 监视脚本，用于直接查看 MCU 电源、电量和看门狗状态。
- 实现 UART 双 APP 分区升级：256 KB Flash 按 Bootloader、升级状态区和 A/B APP 分区划分。RK3562 通过 `/dev/ttyS3` 触发 MCU 进入 Bootloader，升级只写入非活动分区，不覆盖当前可运行固件。
- 升级协议与驱动板 CAN 方案采用相同的状态机思路，按握手、镜像信息、数据传输、结束校验和分区切换组织；数据帧显式携带序号和长度，配合 ACK、超时重传与整包 CRC32。Bootloader 最长等待 120 s 并保持 RK3562 供电，新固件通过启动计数、看门狗和 APP 确认标志完成试启动或回滚；完成多轮真机升级，单轮约 1 分钟。
- 参与 RK3562 用户态链路联调，配合 `CommRouter`、`PeripheralManager` 打通 APK UDP、P401 TUN UDP、UART MAVLink、UDS 外设消息和 `can1` SocketCAN；个人工作集中在 MCU/UART、CAN 接入和板端日志验证。

### 跨设备 CAN 通信与驱动板安全升级

<p class="project-meta">RK3562 控制终端与 RK3588 设备端通过接触式 CAN 链路交换网络信息；RK3588 同时通过 CAN 为 STM32F103CBT6 驱动板更新固件。</p>

- 参与图传快速配对链路开发，主要完成 RK3562 地面端逻辑：读取本地 `tun` MAC，通过扩展 CAN 帧发送 MAC report，解析对端 report 后回复应用层 ACK；重复报文继续 ACK，但不重复触发后续配对动作。
- 前期使用模拟天空端报文检查地面端上报、解析和 ACK，后续参与整机联调，以“硬件接触成功”为起点、“设备端视频出现在控制终端”为终点，完成数十轮接触/断开测试，单轮约 5 s，测试样本内未出现失败。
- 排查 RK3588 外置 CAN 控制器收帧异常时，对照板载晶振检查设备树时钟配置，将参考时钟修正为 25 MHz `fixed-clock`，并绑定到 SPI0 下的两路 `xl2515` 节点；重新构建镜像后，结合 `dmesg`、`ip -d -s link` 和 `candump` 复查控制器及总线状态。
- 在 STM32F103CBT6 的 128 KB Flash 中划分两个 52 KB APP 分区，升级时按该芯片 1 KB Flash 页擦除非活动分区并写入固件，其余空间留给 Bootloader、升级状态和设备参数。升级不改动 Bootloader；传输或整包校验失败时继续从原分区启动。
- 按经典 CAN 单帧最多 8 字节的数据区约束，将升级流程拆为开始、数据、结束/校验等状态；数据帧保留序号后传输固件片段，通过应用层 ACK、超时重传和整包 CRC32 判断升级结果。CAN 标称位速率为 500 kbit/s，约 52 KB 固件单轮升级约 20 s，完成数十轮真机验证。
- 新固件写入后先作为待确认分区启动；结合看门狗、启动计数和 APP 确认标志判断是否运行正常，超时未确认或启动异常时切回旧分区。
- 编写对频、升级和板端部署脚本，使用 `candump`、发送端日志和 MCU 状态定位 CAN 收发、ACK、外置 CAN 控制器及驱动板供电时序问题。
